# MK09 仕様書

Copyright (c) 2026 YUKARI Semiconductor Devices

MK09 の外から見える決まり (システムコール、メッセージ、サーバの要求、ファイルの形式、ハードウェアの前提) を書きます。
どうしてそうなっているかは [DESIGN.md](DESIGN.md)、使い方は [MANUAL.md](MANUAL.md) にあります。
値の定義は `include/mk09.h` `include/proto.h` `include/sysnum.h` にあり、この文書はそれと同じです。

数は 10 進、`$` と `0x` は 16 進です。「u8」「u16」は符号なしの 8 ビット、16 ビット。メモリの中の 16 ビットの値は、
6809 に合わせて**上位バイトが先** (ビッグエンディアン) です。ただし FAT のディスク上の値だけは FAT の約束どおり下位バイトが先です。

## 1. ハードウェアの前提 (sbc09 ボード)

`bsp/sbc09/bsp.h` に書いてあるボードです。シミュレータ `sim09` と、Tang Nano 9K 上の FPGA (`fpga/tn9k`) は同じレジスタを持ちます。

| アドレス | 内容 |
|---|---|
| `$0000-$FEFF` (I/O を除く) | 64KB 全体が RAM。ブート ROM とベクタの `$FF00-$FFFF` だけが ROM |
| `$E000` / `$E001` | ACIA (6850 型) の制御/状態、データ。状態のビット 0 = 受信データあり、ビット 1 = 送信できる (CPU は送信中は止まります)。**割り込みは出ません** (ポーリング) |
| `$E00F` | 電源制御。`$A5` を書くと電源が切れる (シミュレータは終了する) |
| `$E030` | タイマ。`$8F` を書くと開始/確認応答、読んだ値のビット 4 が立っていれば満了。**50Hz の IRQ** |
| `$E031-$E036` | 時計: `$04` を `$E030` に書いてから、年-1900、月、日、時、分、秒 |
| `$E040` | ディスクの命令と結果。`$81` = 読み、`$55` = 書き。結果は読み出して 0 = 成功 |
| `$E041` | ドライブ番号 (0) |
| `$E042-$E044` | セクタ番号 (24 ビット。1 セクタ = 256 バイト。上位から) |
| `$E045-$E046` | DMA のアドレス (上位が先) |
| `$FFF2-$FFFE` | ベクタ: SWI3 → `$0100`、SWI2 → `$0103`、FIRQ → `$010F`、IRQ → `$010C`、SWI → `$0106`、NMI → `$0109`、RESET → `$FF00` |

ディスクは SD カードの生のブロックで、ドライブ 0 のセクタ n は先頭から n×256 バイト目です (512 バイトのブロックの前半/後半)。
`$E040` に命令を書くと、CPU は処理が終わるまで止まります。

## 2. 用語

| 語 | 意味 |
|---|---|
| タスク | カーネルが実行を切り替える単位。番号 (タスク ID) 0..7 |
| サーバ | メッセージを受けて仕事をするタスク (TTY、DISK、FS、PM) |
| メッセージ | 10 バイトの `msg_t` |
| ランデブー | 送る側と受ける側が出会って初めてメッセージが渡る同期の通信 |
| 通知 | 受け手を待たせない、ビットだけの非同期の知らせ |
| グラント | `call` のときにクライアントが渡す「サーバが読み書きしてよいメモリ範囲」 |
| MX | プログラムの実行ファイル (拡張子 `.MX`) |
| TPA | プログラムを読み込む領域 (transient program area) |

## 3. メッセージ

```c
typedef struct msg {
    u8  src;        /* 送った側のタスク ID (カーネルが入れる) */
    u8  op;         /* 要求の番号 / 返事の状態 (0 = 成功、それ以外は E_*) */
    u16 a, b, c, d; /* 引数 / 結果 */
} msg_t;            /* 10 バイト */
```

* 要求では `op` が要求の番号 (サーバごとに決まる、4 章以降)、`a..d` が引数。返事では `op` が**状態** (0 か E_*)、`a..d` が結果です。
* 大きなデータを動かす要求は、`b` にバッファのアドレス、`c` に長さを入れ、`mk_callg()` で**グラント**として渡します。

### 3.1 タスク ID

| ID | 意味 |
|---|---|
| 0 | アイドルタスク (カーネル) |
| 1 | TTY (コンソール) |
| 2 | DISK |
| 3 | FS (ファイルシステム) |
| 4 | PM (プロセス管理) |
| 5..7 | PM が作るタスク (シェル、プログラム) |
| `$FF` (`TID_ANY`) | 受信で「誰からでも (通知も)」 |
| `$FE` (`TID_HW`) | 通知メッセージの `src` |

### 3.2 通知

通知は、受け手が `mk_recv(TID_ANY)` で待っていれば `op = $FF` (`OP_NOTIFY`)、`src = $FE`、`a` = たまったビットのメッセージとして届きます。
待っていなければビットが溜まり (OR され)、次に `TID_ANY` で受信するときにまとめて届きます (特定の相手を指定した受信には届きません)。

| ビット | 名前 | 意味 |
|---|---|---|
| `$0001` | `NFY_TICK` | タイマの 1 周期 (`mk_hook` した 1 つのタスクだけに) |
| `$0002` | `NFY_EXIT` | タスクが終了した (PM に) |
| `$0004` | `NFY_INT` | コンソールで割り込みのキー `^C` が押された (PM に) |
| `$0008` | `NFY_USER` | 利用者の取り決めに使える |

### 3.3 エラー番号

| 値 | 名前 | 意味 |
|---|---|---|
| 0 | `E_OK` | 成功 |
| 1 | `E_PERM` | 許されない (特権の呼び出し、グラントの権利なし) |
| 2 | `E_NOTASK` | そのタスクはない |
| 3 | `E_DEAD` | 相手のタスクが終了した |
| 4 | `E_FAULT` | アドレスや長さがおかしい (自分の領域の外) |
| 5 | `E_NOSLOT` | タスクの空きがない |
| 6 | `E_NOMEM` | メモリの領域が使用中、または不正 |
| 7 | `E_NOTWAIT` | 返事を受ける側が待っていない |
| 8 | `E_INVAL` | 引数がおかしい |
| 9 | `E_NOENT` | ファイルがない |
| 10 | `E_EXIST` | もうある |
| 11 | `E_NOTDIR` | ディレクトリではない |
| 12 | `E_ISDIR` | ディレクトリである |
| 13 | `E_NOSPC` | ディスクがいっぱい |
| 14 | `E_IO` | 装置の誤り |
| 15 | `E_BADF` | ファイルハンドルが違う |
| 16 | `E_MFILE` | 開いているファイルが多すぎる |
| 17 | `E_NOTEMPTY` | ディレクトリが空ではない |

| 20 | `E_BUSY` | 使用中 (別の読み手がいる) |

## 4. システムコール

### 4.1 呼び出しの約束

`SWI` 命令で呼びます (ベクタは `$FFFA` → `$0106` のジャンプ表 → カーネル)。レジスタ:

| 入力 | |
|---|---|
| A | システムコール番号 |
| B | u8 の引数 |
| X, Y, U | 16 ビットの引数 |

| 出力 | |
|---|---|
| B | 状態 (E_*) |
| X | 値 (あるコールだけ) |
| ほかのレジスタ | 呼ぶ前のまま (U も) |

ブロックするコールは、完了したときに B と X が書かれます。C から呼ぶ関数は `lib/mksys.s` のスタブで、
CMOC の呼び出し規約 (引数はスタックに 16 ビットずつ、先頭が最上位、返り値は B / D) です。

特権のコールは、特権フラグのあるタスク (TTY と PM) だけが呼べます。ほかが呼ぶと `E_PERM` です。

### 4.3 メッセージ通信

* **`mk_send(dst, m)`**: `m` を `dst` に渡します。`dst` が `mk_recv` で待っていて (相手を指定した受信なら自分を指定していて)、すぐ渡せれば戻ります。
  待っていなければ、`dst` が受け取るまで**ブロック**します。
* **`mk_recv(from, m)`**: メッセージを受け取ります。`from` が `TID_ANY` なら誰からでも、たまっている通知が先、次に送信待ちのタスク (番号の小さい順)。
  何もなければブロックします。`from` が特定のタスクなら、そのタスクからだけ (通知は来ません)。そのタスクが終了していれば `E_DEAD` です。
* **`mk_call(dst, m)`**: `mk_send` して、**返事を待ちます**。返事は `m` の場所に書かれます (往復の間 `m` は自分の領域に置いたままにします)。
* **`mk_callg(dst, m, gflags)`**: `mk_call` と同じですが、`m->b`..`m->b + m->c` の範囲 (自分の領域の中) を**グラント**として渡します。
  `gflags` は `GR_READ` (1) = サーバが読んでよい、`GR_WRITE` (2) = サーバが書いてよい。
* **`mk_reply(dst, m)`**: サーバが返事を返します。`dst` が待っていなければ**ブロックせずに** `E_NOTWAIT` を返します
  (クライアントが死んでいるとき、サーバが止まらないように)。`dst` が `mk_recv(TID_ANY)` で待っていれば、普通のメッセージとして渡されます。
* **`mk_notify(dst, bits)`**: ブロックしない通知。`dst` が `TID_ANY` で待っていれば `a = bits` のメッセージを渡し、そうでなければ溜めます。
* **`mk_copyfrom(client, off, dst, n)` / `mk_copyto(client, off, src, n)`**: サーバが、自分を呼んで返事を待っているクライアントのグラントの
  `off` バイト目から `n` バイトを、自分のメモリへ読み / 自分のメモリから書きます。次の場合は失敗します:
  `client` がそのサーバの返事を待っていない、またはグラントを渡していない (`E_PERM`)、権利が足りない (`GR_READ` / `GR_WRITE`) (`E_PERM`)、
  `n` が 1024 を超える (`E_INVAL`)、範囲がグラントの外、または自分のメモリの外 (`E_FAULT`)。

アドレスの検査: メッセージ、グラント、`dst`/`src` のバッファは、**そのタスクの領域** (`mk_tinfo` の `lo`..`hi`) の中でなければなりません。外なら `E_FAULT` です。

### 4.4 その他

* **`mk_sleep(ticks)`**: `ticks` ティック (1 ティック = 1/50 秒) 眠ります。0 は `mk_yield` と同じです。
* **`mk_yield()`**: 時間片を手放します。
* **`mk_exit(code)`**: タスクを終了します。待っていた相手は `E_DEAD` を受けます。PM に `NFY_EXIT` が届き、PM が `mk_treap` で回収します。
* **`mk_tinfo(tid, ti)`**:

```c
typedef struct taskinfo {   /* 10 バイト */
    u8  state;      /* TS_FREE 0, READY 1, RECV 2, SEND 3, SLEEP 4, ZOMBIE 5, NEW 6, RUN 7 (自分) */
    u8  prio;       /* 優先度 (小さいほど急ぐ) */
    u16 lo, hi;     /* メモリの領域 */
    u16 sp;         /* 保存されたスタックポインタ */
    u16 cpu;        /* CPU を使ったティック (一巡する) */
} taskinfo_t;
```

* **`mk_hook(bits)`** (特権): 呼んだタスクが、毎ティック `bits` の通知を受けるようにする (全体で 1 つのタスクだけ)。
* **`mk_tcreate(p, &tid)`** (特権): 新しいタスクを作る (状態 NEW)。

```c
typedef struct tcreate {    /* 11 バイト */
    u16 entry;      /* 開始アドレス */
    u16 lo, hi;     /* メモリの領域 [lo, hi) */
    u16 top;        /* 最初のスタックポインタ (lo + 12 <= top <= hi) */
    u16 arg;        /* 最初に X に入る値 */
    u8  prio;       /* 優先度 0..6 */
} tcreate_t;
```

  領域は、ほかの生きているタスクの領域と重なってはいけません (`E_NOMEM`)。`entry` は領域の中、`lo < hi` (`E_INVAL`)。
  タスク ID は 5..7 の空きから割り当てます (なければ `E_NOSLOT`)。
* **`mk_tload(tid, addr, src, n)`** (特権): 状態 NEW のタスクの領域 `addr` に、自分のメモリ `src` から `n` バイトを書き込む。
* **`mk_tstart(tid)`** (特権): NEW のタスクを走らせる。**`mk_tkill(tid, code)`** (特権): タスク 5..7 を終了させる。
  **`mk_treap(&tid, &code)`** (特権): 終了したタスクを 1 つ回収して番号を空ける (なければ `E_NOTASK`)。**`mk_power()`** (特権): 電源を切る。

### 4.5 起動と検査

* ブート時に、アイドル (0) と TTY (1、特権)、DISK (2)、FS (3)、PM (4、特権) が作られて走ります。優先度はサーバが 1、アイドルが 7、利用者のタスクが 4 です。
* スケジューラは、優先度の高い (数の小さい) 準備完了のタスクを選びます。同じ優先度のタスクどうしは時間片 (2 ティック) で順番に走ります。
  準備完了のタスクがなければアイドルが走り、`SYNC` で次の割り込みを待ちます。
* システムコールや割り込みのたびに、カーネルは走っていたタスクのスタックポインタを調べます。
  領域の外、または `lo + 16` より下なら、そのタスクを終了コード `$FD` で終わらせます。

## 5. TTY サーバ (タスク 1)

| 要求 (`op`) | 引数 | 結果 |
|---|---|---|
| `TTY_READ` (1) | `b` = バッファ、`c` = 長さ (グラント `GR_WRITE`) | `a` = 読んだバイト数。**cooked**: 1 行 (最後の `\n` を含む。行が `c` より長ければ続きは次の読みで)。`^D` だけの行は 0 バイト。**raw**: 来ているバイト (1 バイト以上。`TM_NOWAIT` なら 0 でもすぐ返る) |
| `TTY_WRITE` (2) | `b`、`c` (グラント `GR_READ`) | `a` = 書いたバイト数。`TM_CRLF` なら `\n` を `\r\n` にする |
| `TTY_IOCTL` (3) | `a` = 命令 | 下の表 |

読み手は同時に 1 つです (もう 1 つ来ると、前の読み手がまだ待っていれば `E_BUSY`)。

| `TTY_IOCTL` の `a` | 引数 | 結果 |
|---|---|---|
| `TTYC_GETMODE` (1) | | `a` = モード、`b` = 文字コード、`c` = 桁、`d` = 行 |
| `TTYC_SETMODE` (2) | `b` = モード、`c` = 文字コード (`$FFFF` は変えない)、`d` = 桁<<8 \| 行 (`$FFFF` は変えない) | |
| `TTYC_READY` (3) | | `a` = 待たずに読めるバイト数 |
| `TTYC_FLUSH` (4) | | 入力を捨てる |

モードのビット: `TM_RAW` $01 (行編集なし)、`TM_ECHO` $02 (入力の反響)、`TM_CRLF` $04 (出力の LF → CR LF)、`TM_NOWAIT` $08、
`TM_ISIG` $10 (`^C` で PM に `NFY_INT`)。既定は `TM_ECHO | TM_CRLF | TM_ISIG`。文字コード: 0 = 1 バイト、1 = UTF-8、2 = EUC-JP、3 = Shift_JIS (既定 1)。

cooked の行編集: BS / DEL は 1 文字 (多バイト文字の全体) を消し、表示の桁数 (全角 2) だけ画面を戻す。`^U` は行を消す。
`^D` は行の先頭ならファイルの終わり。`^C` (`TM_ISIG` のとき) は `^C` を出して行を捨て、PM に `NFY_INT` を送る。`ESC [ ...` と `ESC O x` のキー列は読み捨てる。
`\r` と `\n` の 1 組は 1 つの改行。1 行は 118 バイトまで。入力のリングバッファは 127 バイトで、ACIA は毎ティックと要求のたびに調べる。

## 6. DISK サーバ (タスク 2)

ブロックは 512 バイト。ブロック番号は 23 ビット (`a` が下位 16 ビット、`d` の下位 8 ビットが上位で最大 `$7F`)、ドライブは `d` の上位 8 ビット。

| 要求 | 引数 | 結果 |
|---|---|---|
| `DISK_READ` (1) | `a` = ブロック下位、`d` = ドライブ<<8 \| ブロック上位、`b` = バッファ、`c` = 512 (グラント `GR_WRITE`) | `op` = 0 か `E_IO` / `E_INVAL` |
| `DISK_WRITE` (2) | 同じ (グラント `GR_READ`) | 同じ |
| `DISK_SIZE` (3) | | `a` = 1 (ドライブがある) |

ブロックは 2 つのセクタで、DMA で 256 バイトのバッファに読み/書きしてから、グラントの前半/後半に写します。

## 7. FS サーバ (タスク 3)

FAT16 のファイルシステムです。起動時にドライブ 0 の MBR からタイプ `$04` `$06` `$0E` の最初のパーティション (MBR がなければブロック 0 のボリューム) を探します。
どの要求も、マウントに失敗していると `E_FORMAT` (再度マウントを試みます)。

### 7.1 要求

パスは `b` = アドレス、`c` = 長さ (終わりの NUL を含む、63 文字まで) で、グラント `GR_READ` として渡します。

| 要求 | 引数 | 結果 |
|---|---|---|
| `FS_OPEN` (1) | `a` = `FO_*`、パス | `a` = ハンドル (0..5) |
| `FS_CLOSE` (2) | `a` = ハンドル | |
| `FS_READ` (3) | `a` = ハンドル、`b`、`c` = バッファと長さ (`GR_WRITE`) | `a` = 読んだバイト数 (0 = 終わり) |
| `FS_WRITE` (4) | `a`、`b`、`c` (`GR_READ`) | `a` = 書いたバイト数 (ディスクが満杯なら少ない/0 で `E_NOSPC`) |
| `FS_SEEK` (5) | `a` = ハンドル、`c:b` = 符号つき 32 ビットの位置 (`b` が下位)、`d` = 0 先頭から / 1 今から / 2 終わりから | `c:b` = 新しい位置。終わりを超える位置は終わりにする (穴は作らない) |
| `FS_STAT` (6) | パス | `a` = 属性、`c:b` = 大きさ、`d` = 日付 (FAT 形式) |
| `FS_READDIR` (7) | `a` = ディレクトリのハンドル、`b` = `dirent_t *`、`c` = 22 以上 (`GR_WRITE`) | `a` = 1 (1 つ返した) / 0 (終わり) |
| `FS_MKDIR` (8) | パス | |
| `FS_REMOVE` (9) | パス (ファイルか空のディレクトリ) | |
| `FS_RENAME` (10) | `b`、`c` = `"旧\0新\0"` (グラント `GR_READ`、全体で 128 バイトまで) | |
| `FS_CHDIR` (11) | パス | |
| `FS_GETCWD` (12) | `b`、`c` = バッファと長さ (`GR_WRITE`) | |
| `FS_SYNC` (13) | | 開いているファイルの大きさを書く |
| `FS_CLOSEALL` (14) | `a` = タスク ID | そのタスクが開いたハンドルをすべて閉じる (PM が使う) |
| `FS_STATFS` (15) | | `a` = 1 クラスタのブロック数、`b` = クラスタ数、`c` = 空き |
| `FS_FSTAT` (16) | `a` = ハンドル | `a` = 属性、`c:b` = 大きさ |
| `FS_CHOWN` (17) | `a` = ハンドル、`b` = タスク ID | ハンドルの持ち主を変える (PM が使う) |

`FS_OPEN` の `a`: `FO_READ` $01、`FO_WRITE` $02、`FO_CREATE` $04、`FO_TRUNC` $08、`FO_APPEND` $10、`FO_DIR` $20 (ディレクトリを開く)、
`FO_EXCL` $40 (`FO_CREATE` と合わせて、あればエラー `E_EXIST`)。ディレクトリを `FO_DIR` なしで開く、`FO_DIR` で書く、は `E_ISDIR`。読み出し専用の
属性のファイルを書こうとすると `E_RO`。

```c
typedef struct dirent {     /* 22 バイト。FS_READDIR の結果 */
    char name[13];          /* "NAME.EXT" (終わりは NUL。"." と ".." も返る) */
    u8   attr;              /* FA_RDONLY 1, FA_HIDDEN 2, FA_SYSTEM 4, FA_VOLUME 8, FA_DIR $10, FA_ARCHIVE $20 */
    u16  sizehi, sizelo;    /* 大きさ (ディレクトリは 0) */
    u16  date, time;        /* FAT 形式: date = (年-1980)<<9 | 月<<5 | 日、time = 時<<11 | 分<<5 | 秒/2 */
} dirent_t;
```

### 7.2 仕様と制限

| 項目 | 内容 |
|---|---|
| 形式 | FAT16 (クラスタ数 4085 以上 65524 以下)。1 クラスタは 2 のべきのブロック数。FAT は 2 つまで |
| ボリュームの大きさ | **65535 ブロック (約 32MB) まで** (ブロック番号が 16 ビット)。大きいボリュームは `E_FORMAT` |
| ファイルの大きさ | 32MB 未満 (ブロック数が 16 ビット) |
| 名前 | 8.3 (名前 8 バイト + 拡張子 3 バイト)。空白、制御文字、`" * + , / : ; < = > ? [ \ ] |` 以外が使える (0x80 以上のバイトも可)。英字 (a-z) は大文字にする。先頭が `$E5` の名前は `$05` で保存 |
| パス | `/` で区切る。`.` と `..` を解釈する。先頭が `/` なら絶対、そうでなければ今のディレクトリから。最後の `/` は無視。63 文字まで |
| 今のディレクトリ | **システム全体で 1 つ**。文字列で覚える (絶対パスに正規化したもの) |
| 長い名前 | 作らない。他のシステムが作った長い名前のエントリは読み飛ばし、短い名前で見える |
| ハンドル | 6 つ (ファイルとディレクトリ共通)。持ち主のタスクが終了すると PM が閉じる |
| キャッシュ | 512 バイトのブロックを 2 つ。書き込みは即座にディスクへ |
| ファイルの大きさの更新 | 閉じるとき、`FS_SYNC` のときに、ディレクトリのエントリに書く |
| 連続するクラスタ | 先頭から連続するクラスタの長さを覚えて (2 つのファイルまで)、そこへのシークは FAT をたどらずに行う |
| 位置と大きさ | (ブロック, 端数) の組で持つ。インタフェースでは 32 ビットを `c:b` の 2 つの 16 ビットで渡す |

## 8. PM サーバ (タスク 4)

| 要求 | 引数 | 結果 |
|---|---|---|
| `PM_SPAWN` (1) | `b`、`c` = `"プログラム\0引数1\0...\0\0"` (グラント `GR_READ`、123 バイトまで)、`a` = 標準入力に使う FS ハンドル (`$FFFF` = コンソール)、`d` = 標準出力に使うハンドル (`$FFFF` = コンソール) | プログラムが**終了したとき**に返る: `a` = 終了コード。始められなければすぐ `op` = エラー (`E_NOENT` `E_FORMAT` `E_NOMEM` ...) |
| `PM_SHUTDOWN` (2) | | `FS_SYNC` して電源を切る (戻らない) |
| `PM_TIME` (3) | | `a` = 日付、`b` = 時刻 (FAT 形式) |

`PM_SPAWN` の引数の 1 つ目は MX ファイルのパスそのものです (探索はシェルがします)。PM は:

1. ファイルを開き、先頭の 16 バイトのヘッダを調べる (9 章)。`ロード番地 < TPA の始め`、または終わりが `$E000` を超えるときは `E_NOMEM`。
2. シェルのいる領域 (シェルの領域と重なるとき) をあけるために、シェルが頼んだのなら**シェルを終了させる** (プログラムが終わったら `sh -r` で読み込み直す)。
   シェル以外が頼んで重なるときは `E_NOMEM`。
3. タスクを作り (`mk_tcreate`)、ファイルを 256 バイトずつ読んで `mk_tload` で書き、起動ブロックを領域の最後に書き、ハンドルの持ち主をその新しいタスクにして、`mk_tstart`。
4. タスクが終了すると、`FS_CLOSEALL` して、終了コードを頼んだ側に返す。シェルがいなければ読み込み直す。

`^C` (`NFY_INT`) を受けると、いちばん新しい子プログラムを終了コード 130 で終わらせます。

## 9. プログラム (MX) とブートイメージの形式

### 9.1 MX ファイル

先頭の 16 バイトがヘッダで、ファイル全体がそのまま `ロード番地` から読み込まれます (ヘッダも含む)。

| オフセット | 内容 |
|---|---|
| 0 | `'M'` `'K'` |
| 2 | 版 (1) |
| 3 | フラグ (予約、0) |
| 4 | ロード番地 (u16) |
| 6 | 開始アドレス (u16、ヘッダの直後) |
| 8 | 予約 |
| 10 | bss の大きさ (u16) |
| 12 | スタックの大きさ (u16) |
| 14 | 予約 |

メモリの領域は `[ロード番地, ロード番地 + ファイルの大きさ + bss + スタック + 128)` です。この 128 バイトが領域の最後にある**起動ブロック**で、
その直前がスタックの底の最初の位置 (スタックポインタ) です。プログラムは X レジスタに起動ブロックのアドレスを受けて開始します。

```
[0] 版 (1)   [1] 標準入力の FS ハンドル ($FF = コンソール)   [2] 標準出力のハンドル   [3] 引数の数
[4..]  "プログラム名\0引数1\0引数2\0..." (NUL で区切った文字列)
```

`crt0app.s` が bss を 0 にし、`INITGL` で初期値のある変数を設定し、起動ブロックから `argc` `argv` (9 個まで) を作って `main` を呼び、
戻ったら `exit` します。ファイルは `lwlink --format=raw` で作ります (`tools/mklink.py` がリンクの指定を書く)。

### 9.2 ブートイメージ

ブート ROM はドライブ 0 のセクタ 2 (256 バイトのセクタ) から順に読み、各セクタを次の形で解釈します:

```
[先 上][先 下][n][n バイトのデータ]     データを先のアドレスに写す (n = 1..253、残りは詰め物)
[開始 上][開始 下][0]                  n = 0 のセクタ: そこへジャンプして終わり
[LSN 上][LSN 下][$FF]                  n = $FF のセクタ: 続きはそのセクタ番号から (n は最大 253 なので $FF は空いている。OS-9 のカーネルのイメージが使う)
```

イメージを作るのは `tools/mkimage.py` (リンクした S レコードから)。`$0200-$02FF` はブート ROM のセクタバッファなので使えません。
ジャンプするのは `$0300` (カーネル) で、カーネルが `$0100` にベクタのジャンプ表を作ります。

### 9.3 ディスクの配置

| ブロック (512 バイト) | 内容 |
|---|---|
| 0 | MBR: 区画表の 1 番目 = 起動可能、タイプ `$06`、開始 2048、大きさ = ボリュームのブロック数。`$55AA` |
| 1 〜 2047 | ブートイメージ (セクタ 2 = ブロック 1 から) |
| 2048 〜 | FAT16 のボリューム (予約 1、FAT 2 つ、ルートディレクトリ 512 エントリ、データ) |

## 10. C ライブラリ (`include/mklib.h`)

返り値は成功なら 0 以上、失敗なら**負のエラー番号**です。ファイル記述子: 0, 1, 2 は標準入出力/エラー (コンソール。0 と 1 は、シェルのリダイレクトで FS ハンドルになる)、
3 以上が FS のハンドル + 3。

| 関数 | 動作 |
|---|---|
| `int open(path, flags)` | `FO_*` で開く。記述子を返す |
| `int close(fd)` / `read(fd, buf, n)` / `write(fd, buf, n)` | 読み書き。`read(0, ...)` は TTY の 1 行 (cooked) |
| `int seek(fd, hi, lo, whence, &rhi, &rlo)` | 位置を動かす (32 ビットを 2 つに分けて渡す。符号つき) |
| `int readdir(fd, dirent_t *)` | 1 つ読む。1 / 0 (終わり) |
| `mkdir` `unlink` `rename` `chdir` `getcwd` `stat` `fstat` `statfs` `sync` | FS の呼び出し |
| `tty_getmode` `tty_setmode` `tty_ready` `tty_flush` | TTY の設定 |
| `int spawn(block, len, in_h, out_h)` | プログラムを実行して終了コードを返す (シェルが使う) |
| `gettime(&date, &time)` `shutdown()` | 時刻、電源断 |
| `putchar` `puts` `putstr` `printf` `fflush` `getchar` `gets_` `exit` | 標準出力は 80 バイトまでためて、改行か一杯になったときに出す (`read(0)` の前にも出す) |
| `utoa_` `atoi_` `isdigit_` `strerr_` | 文字列と数 |

`printf` は `%d %u %x %X %c %s %%`、幅、`-`、`0` に対応します (`l` は読み飛ばし。16 ビットの値)。
