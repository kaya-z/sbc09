# MK09 ユーザーマニュアル

Copyright (c) 2026 YUKARI Semiconductor Devices

MK09 は MC6809 用の小さなマイクロカーネルと、その上で動くコマンド、日本語ワードプロセッサ `jwp` です。
**64KB のメモリだけで動き (MMU は使いません)**、カーネルもプログラムも **SD カードから起動時に読み込まれます**。
シミュレータ `sim09` でも、Tang Nano 9K 上に作った実機 (FPGA) でも、同じ SD カードのイメージで動きます。

* 設計の説明: [DESIGN.md](DESIGN.md)　　仕様 (システムコール、メッセージ、ファイル形式): [SPEC.md](SPEC.md)

> **確認していること / していないこと**
> `sim09` では、起動、シェル、各コマンド、`jwp` (UTF-8 / EUC-JP / Shift_JIS)、SKK 変換、ファイルの読み書きを自動テストで確認しています
> (`make test`)。Tang Nano 9K は、FPGA の RTL を Verilator で動かしたモデルの上で起動、`ls`、ファイル作成、SD カードへの書き込み、電源断を確認しました。
> 実機の Tang Nano 9K でも、USB シリアルのコンソールで、起動、`ls` `ps` `df` `date`、ファイルの作成と読み出し、`dhry`、`jwp` (日本語の入力と保存) を確認しました (2026-10-15)。
> **HDMI の画面は、MK09 では確認していません。**

## 1. 動かす

### 1.1 ビルド

必要なもの: Linux (Debian 12 で確認)、`make`、`gcc`、`python3`、`iconv`、6809 用の C コンパイラ **CMOC** と **lwtools**
(`../tools/install_cmoc.sh` で入れられます)、辞書を付けるなら Debian の `skkdic` パッケージ (`/usr/share/skk/SKK-JISYO.L`)。

```sh
tools/install_cmoc.sh $HOME/cmoc        # 一度だけ。lwtools と CMOC を $HOME/cmoc に作る (ネットワークが要ります)
make                                    # シミュレータ sim09 を先に作っておく
cd mk09
make CMOC_BIN=$HOME/cmoc/bin            # build/ にカーネル、プログラム、ブート ROM、ディスクイメージ mk09.img を作る
```

作られるもの (`mk09/build/`):

| ファイル | 内容 |
|---|---|
| `bootrom.bin` | ブート ROM (256 バイト)。FUZIX のブート ROM と**バイト単位で同じ**です |
| `mk09.img` | SD カードの中身 (MBR + ブートイメージ + FAT16 のボリューム)。既定は約 17MB |
| `boot.img` | カーネルとサーバのブートイメージ (`mk09.img` に入っています) |
| `*.mx` | プログラム (`/BIN` に入っています) |
| `tree/` | ディスクに入れるファイルの木 |

オプション:

| 指定 | 意味 |
|---|---|
| `make CHARSET=euc` | コンソールと辞書を EUC-JP にする (`utf8` (既定) / `euc` / `sjis`)。`jwp` と辞書は文字コードごとに作ります |
| `make charsets` | `build_euc/` と `build_sjis/` に EUC-JP 版と Shift_JIS 版も作る |
| `make JWP_BUF=8000` | `jwp` の文章用バッファの大きさ (既定 11500 バイト) |
| `make SKK_KB=600` | 辞書を約 600KB に絞る (短い読みの語を優先)。0 は全部 (約 5MB) |
| `make DISK_MB=30` | ディスクイメージの大きさ (FAT の部分は 32MB まで) |
| `make KERNEL=c` | 6809 のアセンブラ版ではなく、移植用の C 版カーネルにする (`B=build_c` と併せて別の場所に作る) |
| `make test` | 自動テスト一式 |

### 1.2 シミュレータで動かす

```sh
./sim09 -rom mk09/build/bootrom.bin -0 mk09/build/mk09.img -kanji utf8
```

* `-kanji utf8` は、端末が UTF-8 のとき (既定の `CHARSET=utf8` のディスク用) です。EUC-JP のディスクなら `-kanji euc`、Shift_JIS なら `-kanji sjis` を付けます。
  端末の文字コードがそのままで良ければ付けなくても動きます。
* 速く動かすには `-max` を付けます (実時間に合わせない)。
* 止めるときは、MK09 の中で `shutdown` と打つか、`Ctrl-]` で出るモニタで `q` です。

### 1.3 実機 (Tang Nano 9K) で動かす

MK09 は FUZIX と同じ形式のブート ROM を使うので、**FUZIX 用に書き込んだビットストリームをそのまま使えます** (`fpga/tn9k/scripts/build.sh fuzix`
で作ったもの。書き込み方は [../../docs/FPGA.md](../../docs/FPGA.md))。変えるのは SD カードの中身だけです。

```sh
# /dev/sdX は必ずカードのデバイスを確かめてください。間違えると、そのディスクを壊します。
sudo dd if=mk09/build/mk09.img of=/dev/sdX bs=512 conv=fsync
```

カードを基板に差して電源を入れると、ブート ROM がカードの先頭から (セクタ 2 以降) カーネルとサーバを読み込んで起動します。
コンソールは USB シリアル (115200bps) と、HDMI の文字画面です。HDMI の文字画面は UTF-8 / EUC-JP / Shift_JIS の漢字を出せます。
HDMI の画面の文字コードは、ビットストリームを作るときに決まります (既定は UTF-8。`HDMI_CHARSET=2` などで変える)。動いている間は `stty hdmi` で切り替えられます
(`stty euc hdmi` のように、文字コードと一緒に指定します。端末に `ESC % G` / `E` / `S` を送ります)。

* 時計は電池がなく、ビットストリームを作った日時から数えます (`date`)。
* カードの FAT 部分は **32MB 以下**です。それより大きいカードでも、残りは使いません。

## 2. シェルとコマンド

起動すると、まず `MK09: kernel ...` `MK09: disk ...` `MK09: fs ...` `MK09: loading /BIN/SH.MX` の 4 行で起動の経過が出ます。続いて `MK09` のロゴと `MC6809 microkernel 1.0 ... type help` という案内が出て、`/> ` というプロンプトが出ます (`/` は今のディレクトリです)。
1 行を打って Enter で実行します。行の編集は、BS / DEL で 1 文字 (全角文字は 1 文字)、`^U` で行全体の取り消し、`^D` (行の先頭で) でファイル終わりです。

* **コマンドの探し方**: `名前.MX` を今のディレクトリ、次に `/BIN` から探します。名前に `/` があれば、そのパスのとおりです。
* **リダイレクト**: `コマンド > ファイル` (作り直し)、`>> ファイル` (追加)、`< ファイル` (入力)。
* **引用符**: `"` と `'` で空白を含む語を作れます。`#` で始まる行は注釈です。
* **`^C`**: 実行中のプログラムを止めます (行の入力中は、行を捨てます)。
* ファイル名は **8.3 形式** (名前 8 バイト + 拡張子 3 バイト) で、英字の大文字と小文字は区別しません (ディスクには大文字で入ります)。
  日本語のファイル名もそのバイト数の範囲で使えます (UTF-8 では全角 1 文字が 3 バイトです)。

### 組み込みコマンド

| コマンド | 動作 |
|---|---|
| `cd [場所]` | ディレクトリを変える (引数なしは `/`)。**今のディレクトリはシステム全体で 1 つ**です |
| `pwd` | 今のディレクトリを出す |
| `source ファイル` / `. ファイル` | ファイルの行をシェルのコマンドとして実行する (入れ子は 2 段まで) |
| `sync` | ディスクに書き込む (書き込みはその都度ディスクに行くので、通常は要りません) |
| `shutdown` / `halt` | 電源を切る (シミュレータは終了する) |
| `exit [n]` | シェルを終える (すぐ起動し直されます) |
| `ver`, `help` | 版とコマンドの一覧 |

起動時に `/ETC/RC.SH` があれば `source` します。標準では `stty utf8` (ディスクの文字コード) だけが入っています。

| `cat [ファイル...]` | ファイルを出す (引数なしは標準入力) |

| `cp 元 先` | コピー (先がディレクトリなら、その中へ) |
| `mv 元 先` | 名前を変える、移す (先がディレクトリなら、その中へ。ディレクトリも移せる) |
| `rm ファイル...` | 消す (空のディレクトリも) |
| `mkdir 名前...` | ディレクトリを作る |
| `date` | 日付と時刻 |
| `df` | ディスクの空き (クラスタ数と KB) |
| `ps` | タスクの一覧 (状態、優先度、メモリの範囲、CPU 時間) |
| `stty [設定...]` | コンソールの設定。下の表 |
| `hd ファイル` | 16 進ダンプ |
| `wc [ファイル]` | 行数、語数、バイト数 |
| `jwp [-w 桁] [-h 行] [-e 桁] [-d 辞書] [-u 辞書] [ファイル]` | 日本語ワープロ (3 章) |

`stty` の設定 (複数並べられます。引数なしは今の設定を出します):

| 設定 | 意味 |
|---|---|
| `utf8` / `euc` / `sjis` / `ascii` | 端末の文字コード (行編集と `jwp` がこれで文字を数えます) |

| `hdmi` | FPGA 基板の HDMI 画面に文字コードを知らせる (`ESC % G` / `E` / `S` を出す)。ほかの端末では使わないでください |

## 3. 日本語ワードプロセッサ `jwp`

全画面の日本語ワードプロセッサです。OS-9 用の `jwp` ([../../docs/JWP.md](../../docs/JWP.md)) を MK09 に移したもので、操作は同じです。

* 全角文字は 2 桁で表示し、カーソル移動、削除、バックスペースは**文字単位**です。
* 画面の幅で**自動折り返し**します (行頭禁則、行末禁則。英単語は空白で折り返す)。折り返しは表示だけで、ファイルには入りません。
* 変更したところだけを描き直します (端末の行挿入・行削除を使うので、スクロールが速い)。
* 検索、切り取り/貼り付け、**整形出力** (折り返しを実際の改行にした印刷用ファイル) があります。
* **SKK 方式のかな漢字変換**があります。辞書は**メモリに読み込まず、SD カードの上のファイルを二分探索**します。
* ファイルの改行 (LF / CR / CRLF) を自動判定して、同じ形式で書き戻します。新しいファイルは LF です。
* 文章用のバッファは 11500 バイトです (UTF-8 で約 3800 字、EUC-JP / Shift_JIS で約 5700 字)。それより大きいファイルは、
  入る分だけ読み込み、`ファイルが大きすぎます` と出て、**保存を拒否**します (元のファイルを壊さないため)。

端末の日本語入力 (IME) で入力した文字は、そのまま入ります。端末の文字コードと `jwp` の文字コードは同じでなければなりません。
`jwp` は UTF-8 / EUC-JP / Shift_JIS のどれか 1 つ用に作ってあり (`make CHARSET=...`)、起動時にコンソールの設定を自分の文字コードに合わせます。

### 3.1 起動

```
/> jwp memo.txt             ファイルを開く (なければ新規)
/> jwp -w 60 -e 36 手紙.txt   窓幅 60 桁、整形出力の幅 36 桁
```

| オプション | 意味 |
|---|---|
| `-w 桁` | 窓の幅 (20..90、既定はコンソールの設定、通常 80) |
| `-h 行` | 窓の高さ (6..28、既定 24。下 2 行はステータス行とメッセージ行) |
| `-e 桁` | 整形出力 (`^X`) の幅 (10..90、既定 72) |
| `-d ファイル` | SKK 辞書 (既定 `/SKK/SKK.DIC`) |
| `-u ファイル` | SKK のユーザ辞書 (既定 `/SKK/USER.DIC`) |

画面の下から 2 行目 (反転) がステータス行です: ファイル名、`[変更]`、桁 (全角は 2)、位置/バッファの大きさ、改行形式、文字コード、入力モード。
一番下の行はキーの一覧、または直前の操作のメッセージです。**終わるときは `^Q`** です。そのあと、シェルが自動的に戻ってきます
(`jwp` はメモリを広く使うので、実行中はシェルがメモリから外れ、終わると読み込み直されます。今のディレクトリは変わりません)。

### 3.2 キー

| キー | 動作 | キー | 動作 |
|---|---|---|---|
| `←` `→` / `^B` `^F` | 1 文字 左/右 | `^S` | 保存 |
| `↑` `↓` / `^P` `^N` | 1 行 上/下 (表示桁を保つ) | `^W` | 名前を付けて保存 |
| `^A` `^E` / `Home` `End` | 行頭 / 行末 (表示行) | `^O` | 別のファイルを開く |
| `PgUp` `PgDn` / `^U` `^V` | 1 画面 上/下 | `^R` | 検索 (文字列を入力して Enter) |
| `ESC <` / `ESC >` | 文書の先頭 / 末尾 | `^T` | 次を検索 (最後まで行くと先頭に戻る) |
| `BS` `^H` `DEL` | カーソルの左の 1 文字を削除 | `^K` | 行末まで切り取り (行末では改行を切る) |
| `^D` / `Delete` | カーソルの位置の 1 文字を削除 | `^Y` | 貼り付け (`^K` を続けると溜まる) |
| `Enter` | 改行 (段落を区切る) | `^X` | 整形出力 |
| `Tab` | 全角空白 (字下げ) を入れる | `^G` | 改行形式を LF → CRLF → CR と切り替え |
| `^L` | 画面を描き直す | `^Q` | 終了 (変更があれば確認) |
| `^J` | かな入力モードにする (SKK) | `l` | (かなモードで) 英数モードに戻す |

ファイル名などの入力行では `BS` が 1 文字ずつ、`Enter` で確定、`^G` で取り消しです。`^W` と `^O` では最初に今のファイル名が入っているので、
`BS` で消してから新しい名前を打ってください。`jwp` の実行中は `^C` も `jwp` に渡るので、`^C` で止めることはできません (`^Q` で終わります)。

### 3.3 折り返し (禁則処理)

* 行頭に来てはいけない文字 (`、。，．・：；？！゛゜ゝゞ々ーぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮヵヶ）〕］｝〉》」』】` と ASCII の `,.:;?!)]}`) は、
  前の文字を巻き込んで (最大 3 文字) 次の行へ送ります。
* 行末に来てはいけない文字 (`（〔［｛〈《「『【` と ASCII の `([{`) は、次の行へ送ります。
* 英数字の単語は、行に入りきらないとき最後の空白で折り返します。
* 文字の表示幅は、UTF-8 では全角・ひらがな・カタカナ・漢字・全角記号が 2、半角カナと `※` `○` `→` などの曖昧幅が 1 です。
  EUC-JP / Shift_JIS では 2 バイト文字が 2、半角カナが 1 です。

### 3.4 整形出力

`^X` でファイル名を入力すると、**折り返しを実際の改行にした**ファイルを作ります (幅は `-e`、既定 72 桁、禁則処理つき)。元の文書はそのままです。

### 3.5 かな漢字変換 (SKK)

端末の IME がなくても、MK09 の中だけで日本語を入力できます。起動時は英数モードで、状態はステータス行の最後に `かな` / `カナ` / `英数` と出ます。

| 操作 | 動作 |
|---|---|
| `^J` | 英数モード → ひらがなモード (かなモードでの `^J` は Enter) |
| `l` | かなモード → 英数モード |
| `q` | ひらがな ⇄ カタカナ (読みの入力中なら、読みをカタカナにして確定) |
| ローマ字 | `ka`→か `kya`→きゃ `kitte`→きって `kanji`→かんじ `onna`→おんな `-`→ー `,`→、 `.`→。 `[`→「 `]`→」 |
| 大文字から始める | `Kanji` で読みの入力 `▽かんじ` (大文字は読みの始まり) |
| `Space` | 変換。`▼漢字` のように候補を見せる。もう一度 `Space` で次の候補、`x` で前の候補 |
| 5 つ目の候補から | 下の行に `a:候補 s:候補 d:… f: j: k: l:` が並び、そのキーで選べる (`Space` は次の 7 つ) |
| `Enter` / 他のキー | 候補を確定 (`Enter` では改行しない。他のキーは確定してからそのキーの動作) |
| `^G` | 変換を取り消して `▽` の読みに戻る / 読みの入力を取り消す |
| `BS` | 読みの 1 文字を消す |
| 送り仮名 | 送り仮名の頭を大文字に: `KaKu`→`書く`、`OkuRu`→`送る`、`TabeRu`→`食べる` |
| `/` | 略語モード: `/abc` + `Space` で ASCII の読みを引く |
| 候補がないとき | `辞書登録 よみ:` と聞くので、語を入力して Enter (ユーザ辞書に登録され、そのまま入る)。空なら取り消し |

* `▽` `▼` は文書の中に入る文字で、確定するか取り消すと消えます。
* 先頭以外の候補を選ぶと、ユーザ辞書に `よみ /候補/` が追加され、**次からはその候補が先頭**に出ます (学習)。
* 未対応: 連文節変換、全角英数モード、数値変換、接頭辞/接尾辞、Lisp の候補 `(concat ...)` (読み飛ばします)、注釈 (`;` 以降は捨てます)。
* **変換には 1 秒余りかかります** (1.8432 MHz の 6809 で、5MB の辞書を SD カードの上で二分探索するため)。

#### 辞書

辞書は SKK の辞書と同じ 1 行 1 語のテキスト (`よみ /候補/候補/`) で、**読みの順に整列**してあります。行末は CR で、
文字コードは MK09 のコンソールと同じです。`make` が `SKK-JISYO.L` から `tools/mkskkdic.py` で作り、`/SKK/SKK.DIC` に入れます。
`jwp` は辞書をメモリに読み込まず、256 バイトのブロック単位で二分探索します。SKK の辞書を自分で入れ替えるには:

```sh
python3 tools/mkskkdic.py -e utf8 -o skk.dic /usr/share/skk/SKK-JISYO.L       # -e euc / sjis, -b 600 で約 600KB に絞る
```

作った `skk.dic` をディスクイメージの `tree/skk/` に入れて `mkdisk.py` で作り直すか、`jwp -d` で別の場所を指します。
ユーザ辞書 `/SKK/USER.DIC` は `jwp` が追記します (ディレクトリ `/SKK` が要ります)。
辞書が見つからないときは `辞書がありません` と出て、語は登録の問い合わせになります。

## 4. ディスクとファイル

### 4.1 SD カードの形

```
ブロック 0          MBR (パーティション 1: FAT16, ブロック 2048 から)
ブロック 1 ..        ブートイメージ (カーネルとサーバ。ブート ROM が読む。最大約 1MB)
ブロック 2048 ..     FAT16 のボリューム (最大 32MB)
```

**カードは PC からも読めます**。PC に差すと、1 つの FAT16 パーティションとして見えます (ファイルを入れたり、`jwp` の文書を取り出したりできます)。
ただし MK09 は 8.3 形式の名前だけを扱います。PC が付けた長いファイル名は、短い名前 (`~1` のもの) で見えます。
ブートイメージは最初のパーティションの前にあるので、PC でフォーマットし直すと消えます。作り直すには `mkdisk.py` か `dd` です。

### 4.2 自分のファイルを入れてディスクイメージを作る

```sh
mkdir -p tree/doc; cp メモ.txt tree/doc/            # 名前は 8.3 に収まること (mkdisk.py が確かめます)
python3 tools/mkdisk.py -o my.img --boot build/boot.img --size-mb 30 tree
```

`tree` の下の構造がそのままボリュームになります (`tree/bin/*.mx` がコマンド)。

### 4.3 ファイルシステムの制限

* FAT16 だけ、ボリュームは **32MB まで** (ブロック番号が 16 ビットなので)。1 ファイルも 32MB まで。
* 名前は 8.3 形式。長い名前は作れません。日付と時刻は、時計から入ります。
* 同時に開けるファイルは 6 つ (ディレクトリを含む)。
* 今のディレクトリはシステムに 1 つです (プログラムごとではありません)。
* ディスクに書いた内容は、その都度ディスクに行きます。ただし、開いているファイルの大きさと先頭クラスタは閉じたときに書かれるので、
  書いている最中に電源を切ると、そのファイルの最後の部分が失われます。`shutdown` を使ってください。

## 5. 自分のプログラムを作る

プログラムは C (CMOC) か 6809 のアセンブラで書きます。`mk09/apps/` に例があります。最小の例:

```c
/* apps/hello.c */
#include "types.h"
#include "mklib.h"

int main(int argc, char **argv)
{
    printf("Hello, %s\n", argc > 1 ? argv[1] : "world");
    return 0;
}
```

`Makefile` の `APPS := ...` に `hello` を足して `make` すると、`build/hello.mx` ができて、ディスクの `/BIN/HELLO.MX` に入ります。
使える関数は `include/mklib.h` に一覧があります (`open` `read` `write` `seek` `readdir` `mkdir` `unlink` `rename` `chdir`、
`printf` `puts` `putchar`、`tty_getmode` `tty_setmode`、`spawn` など。[SPEC.md](SPEC.md) の 10 章)。

* 返り値は、成功なら 0 以上、失敗なら**負のエラー番号** (`-E_NOENT` など。`strerr_(r)` で文字になります)。
* メモリは、プログラム本体 + 初期化データ + 領域 (bss) + スタック (`STACK_名前` で変えられる、既定 512 バイト) で、**1 つの連続した領域**にまとめて読み込まれます。
  malloc はありません。大きな配列は静的に取ります。
* 使えるメモリは約 41KB です。それを超えるプログラムは、読み込むときに `error 6` (メモリ不足) になります。
* 6809 用の C コンパイラ CMOC の癖があります (`char` は符号付き、`u8 << 8` が 0 になる、`unsigned char` どうしの掛け算が 8 ビットで切れる、
  文字列へのポインタの静的な配列が書けない、など。[DESIGN.md](DESIGN.md) の 12 章)。

## 6. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 何も出ない (実機) | SD カードにイメージが入っているか。ビットストリームは FUZIX 用 (`ROM=fuzix`) のものを使う。USB シリアルは 115200bps、ハードウェアフロー制御なし |
| `MK09: cannot start /BIN/SH.MX (error 9)` | シェルが見つからない。SD カードの FAT の部分が壊れているか、イメージが違う |
| 文字化けする | `stty utf8` / `euc` / `sjis` を端末に合わせる。`jwp` はビルドした文字コードに合わせて設定を変えます |
| `jwp` が `辞書がありません` | `/SKK/SKK.DIC` がない (`skkdic` なしでビルドした)。上の「辞書」を見る |
| `command not found` | `/BIN/名前.MX` がない、または `cd` したディレクトリに `名前.MX` がない |
| `error 6` | プログラムがメモリに入らない (約 41KB まで) |
| 電源断のあとファイルが短い | 閉じる前に切った。`shutdown` を使う |
| 全角のファイル名が PC で化ける | 名前の文字コードは端末と同じ (UTF-8 など)。PC の FAT は OEM コードページで読む |
