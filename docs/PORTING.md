# jwp の機種依存と移植の手引き

日本語ワードプロセッサ `jwp` (`os9/jwp/`、使い方は [JWP.md](JWP.md)) が、どの機種・環境に依存しているかをまとめます。
シミュレータ固有のハードウェアには依存していませんが、**端末の種類**、**文字コードの伝え方**、**OS-9 の種類とメモリ**に依存します。

> **確認していること / していないこと**
> `jwp` を動かして確認したのは、このリポジトリのシミュレータ `sim09` 上の NitrOS-9 Level 1 / Level 2 だけです。
> 実機 (FM-11、CoCo、Dragon など) や他の OS-9 では動かしていません。以下の「動くはず」は、コードの依存を調べた推論です。

## 1. 依存の一覧

| 区分 | 依存するもの | 依存しないもの | 変えるには |
|---|---|---|---|
| CPU | MC6809 (CMOC が出力する 6809 の命令だけ。6309 専用命令は不使用) | シミュレータの CPU コア | — |
| OS | OS-9 (6809) の Level 1 / Level 2 | シミュレータの I/O レジスタ、MMU の構成、VRBF (`/v0`) | — |
| 端末 | ANSI (VT100 系) の制御列とキー入力 | FM-11 などの専用画面 | 4 章 |
| 文字コード | 改造した SCF が `PD.PAR` で伝える取り決め | 標準の SCF | 3 章 |
| メモリ | Level 1: 空き約 44KB、Level 2: 1 プロセス 64KB | — | 6 章 |
| ディスク | 標準の RBF (256 バイトセクタ、32 ビットのシーク) | 特定のドライバ | 7 章 |
| ビルド | CMOC + LWTOOLS (ソースから作り直すときだけ) | — | 8 章 |

## 2. OS-9 のシステムコール

使うのは OS-9 の標準的な呼び出しだけです (`os9/jwp/jwp.c` の `sc_*` ラッパー)。

| コール | 用途 |
|---|---|
| `I$Open` (`$84`) / `I$Create` (`$83`) / `I$Close` (`$8F`) / `I$Delete` (`$87`) | 文書、辞書、ユーザ辞書のファイル |
| `I$Read` (`$89`) / `I$Write` (`$8A`) | 端末 (パス 0 から入力、パス 1 へ出力) とファイル |
| `I$Seek` (`$88`) | 辞書の二分探索 (32 ビットの位置を `X:U` で渡す) |
| `I$GetStt` (`$8D`) `SS.Opt` (`$00`) / `SS.Ready` (`$01`) / `SS.Size` (`$02`) | 端末オプションの取得、入力待ちの確認、ファイルサイズ |
| `I$SetStt` (`$8E`) `SS.Opt` | 端末を生入力にする設定と、終了時の復元 |

`F$Mem` `F$Fork` `F$Link` `F$Sleep` などは使いません。信号 (`F$Icpt`) も使いません。端末のパスは `^C` `^E` などを無効にして
受け取るので、`jwp` の実行中はキーボードからの割り込みで中断できません。

CMOC の注意点として、グローバル変数は `Y` レジスタ経由で参照され、フレームポインタは `U` です。asm のラッパーは、
グローバルに書く前に `Y` を戻し、`SS.Size` や `I$Seek` で `U` が壊れる呼び出しは `U` を保存しています (`sc_size` `sc_seek`)。
別の機種へ持っていくとき、このコードを書き換えなくても、OS-9 の ABI が同じなら動きます。

## 3. 文字コード: 改造 SCF への依存 (いちばん大きな依存)

`jwp` は起動時に、端末のパス 0 に `SS.Opt` を発行し、**32 バイトのオプション領域の 20 バイト目 (`PD.PAR`) を文字コードとして読みます**。

| `PD.PAR` | 意味 | 効果 |
|---|---|---|
| 0 | 1 バイト文字 | 日本語の編集も SKK も無効 (メッセージは英語、8 ビットをそのまま通す) |
| 1 | UTF-8 | 全角は 2 桁、カーソルと削除は文字単位、SKK 有効 |
| 2 | EUC-JP | 同上 |
| 3 | Shift_JIS (CP932) | 同上 |
| 4 以上 | — | 0 として扱う |

**`PD.PAR` は本来 OS-9 ではパリティの指定**です。このリポジトリの SCF (`os9/kanji/scf.asm`) は、SCF のドライバで使われていない
このフィールドを、行編集 (BS、文字の幅) のための文字コードの指定に流用しています (`kmode` コマンドで見る・変える)。
そのため次のことが起きます。

* 標準の NitrOS-9 の SCF では、`PD.PAR` は 0 かパリティの値です。0 なら `jwp` は 1 バイト文字として動きます。パリティの値が
  たまたま 1〜3 だと、文字コードと誤認します。
* ホスト側の文字コード変換 (UTF-8 の端末 ⇔ ゲストの EUC-JP など) は、このシミュレータのコンソール (`-kanji`) の機能で、
  OS-9 の外にあります。実機の端末が文字コードを変換してくれるかどうかは、その端末次第です。
* 辞書ファイルと文書は、端末と**同じ文字コードのバイト列**です。変換はしません。

**ほかの環境で使うには**: `PD.PAR` を同じ意味で使う SCF にするか、`jwp` に文字コードを指定するオプションを足します
(`main()` の `enc = opts[20]` の部分を、引数の値に置き換えるだけです)。このオプションは現在ありません。

## 4. 端末への依存

### 4.1 出力

出力はすべてパス 1 への `I$Write` で、次の ANSI の制御列だけを使います。ほかに文字の出力 (文書の文字、ステータス行) があります。

| 制御列 | 意味 | 使う場所 |
|---|---|---|
| `ESC [ 2 J`, `ESC [ H` | 画面消去、ホーム | 起動、`^L` |
| `ESC [ r ; c H` | カーソルの位置 | すべての描画、カーソルの表示位置 |
| `ESC [ K` | 行末まで消去 | 行を描く前 (右端での折り返し状態を避けるため、描く**前**に消す) |
| `ESC [ 7 m`, `ESC [ m` | 反転、属性解除 | ステータス行 |
| `ESC [ 1 ; N r`, `ESC [ r` | スクロール領域の設定と解除 | 行の挿入と削除 |
| `ESC [ n L`, `ESC [ n M` | 行の挿入、行の削除 | スクロール、改行の高速な描き直し |

上の表にない制御列は使いません。カーソルの表示と消去、色、代替画面、`DSR` (カーソル位置の問い合わせ) は使いません。
端末サイズも問い合わせず、`-w` / `-h` (既定 80x24) で決めます。

**端末が `IL` / `DL` (行の挿入と削除) を持たない場合**: 行の移動を端末に任せる部分 (`plan()` が `scrollrows()` を呼ぶところ) を、
「移った行をすべて描き直す」に変える必要があります (`plan()` で一致した行を `rdirty = 0` にしている部分を外せば、描き直しだけで動きます)。
今は切り替えのオプションがありません。

### 4.2 文字の幅

画面の桁の計算は端末と合っている必要があります。

* UTF-8 では Unicode の東アジアの幅に従い、全角 (ひらがな、カタカナ、漢字、全角記号) を 2、半角カナを 1、`※` `○` `→` `▽` `▼` などの
  曖昧な幅を 1 とします。端末が曖昧な幅を 2 で描く設定だと、その行は 1 桁ずつずれます。
* EUC-JP / Shift_JIS では 2 バイト文字を 2、半角カナを 1 とします。ホスト端末が UTF-8 のとき `▽` `▼` も 2 とみなすので、
  これらを含む行はずれます (表示だけで、データは壊れません)。

### 4.3 入力

| キー | 期待するバイト列 |
|---|---|
| 文字 | 端末の文字コードのバイト列 (多バイト文字は続きのバイトを読んで 1 文字として扱う) |
| Enter | `$0D` (`$0A` も改行扱い。ただし SKK のかなモードでは `$0A` = `^J`) |
| BackSpace | `$08` または `$7F` |
| カーソルキー | `ESC [ A/B/C/D`、`ESC O A/B/C/D` |
| Home / End / PgUp / PgDn / Delete | `ESC [ H` `ESC [ F`、`ESC [ 1~` `4~` `7~` `8~` `5~` `6~` `3~` |
| 代替 (Emacs 風) | `^A ^B ^D ^E ^F ^N ^P ^U ^V`、`ESC v` `ESC <` `ESC >` |

`ESC` を受け取ったら、**続きのバイトを待ちます** (時間切れの判定はしません)。`ESC` だけを押すキーボードの端末では、次のキーが
`ESC` の続きとして扱われます。

### 4.4 端末オプション (`SS.Opt`)

`jwp` は起動時に、パス 0 のオプションを取得し、次のフィールドを 0 にして設定し、**終了時に元へ戻します**。

| オフセット | フィールド | 理由 |
|---|---|---|
| 1 | `PD.UPC` | 大文字化を止める |
| 4 | `PD.EKO` | エコーを止める (`jwp` が描く) |
| 5 | `PD.ALF` | 自動の LF を止める |
| 7 | `PD.PAU` | 1 ページごとの停止を止める |
| 9〜17 | `PD.BSP DEL EOR EOF RPR DUP PSC INT QUT` | SCF は `I$Read` の 1 文字目でも `PD.EOF` (既定 `^D`) を見るので、`^D` などが渡らない。すべて 0 にして全部のキーを受け取る |
| 24, 25 | `PD.XON` `PD.XOFF` | `^Q` `^S` を受け取る |

`PD.PAR` (20) は変えません。これらのオフセットは NitrOS-9 の `scf.d` (`PD.OPT` からの位置) のものです。ほかの SCF 互換のドライバで
意味が違えば、ここを直します。

## 5. 6809 / CMOC の制約

* `int` は 16 ビットです。文書内の位置は `int` なので、バッファは 32000 バイト以下です。
* `char` は符号つきです (CMOC)。バイトの比較は `unsigned char` にして行っています。
* モジュール名は**出力ファイル名**になります。パスを付けてビルドすると、モジュール名が長すぎて
  Level 1 で読み込めません (`ERROR #206`)。`-o jwp` でビルドします。
* 文字列リテラルの 8 進エスケープは CMOC が処理しません。日本語のメッセージは `genmsgs.py` がバイト配列として生成します (`msgs.h`)。

## 6. メモリ

| | Level 1 | Level 2 |
|---|---|---|
| モジュール | 約 29KB (コード、ROM のデータ、文字列) | 同じ |
| 文書バッファ | 9000 バイト | 26000 バイト |
| 限度の理由 | 空き RAM 約 44KB (モジュールを読み込む場所 + データ)。10000 バイトでは `ERROR #207` | 1 プロセス 64KB、プログラムとデータを 8KB 単位に切り上げて収める。30000 バイトでは起動しない (SKK なしの版での測定) |

バッファの大きさは `-DBUFSZ=n` で変えられます (`os9/jwp/Makefile` の `jwp-l2`)。これ以外に、行の配置 (最大 40 行、100 桁)、
カット用バッファ (512 バイト)、SKK の作業領域 (約 2KB) などが静的に取られています。**空き RAM が 44KB より少ない機械**
(たとえば 64KB の CoCo 2 に標準の Disk BASIC 系の OS-9 を載せた構成) では、バッファをさらに小さくするか、機能を外す必要があります。

## 7. ディスク

* 文書は普通の OS-9 のファイルで、行末は CR / LF / CRLF を自動判定して保存します。
* 辞書 (`skk.dic`) とユーザ辞書 (`skkuser.dic`) は、既定では `/d1` にあります (`-d` / `-u` で変更)。
* 辞書は 4〜5MB のファイルを `I$Seek` の 32 ビットの位置で二分探索します。**1 つのファイルが 4MB を超える**ので、
  RBF のセグメントリスト (1 ファイル最大 48 セグメント) に収まるよう、連続した領域に置く必要があります。`tools/mkrbf.py` は
  1 つのセグメントで作ります。実機のフォーマッタで作ったディスクに `copy` すると、断片化するかもしれません。
* 辞書のブロックの読み出しは 256 バイト単位です。実機のフロッピーでは、1 回の変換で十数回のシークが起きます (シミュレータでは 0.3〜0.4 秒)。
* ユーザ辞書は追記だけで、ディスクに書き込みます。書き込み禁止のディスクでは学習と登録が失敗し、エラー番号をメッセージ行に出します。

## 8. ビルド環境

実行に必要なのはビルド済みの `os9/jwp/jwp` と `jwp-l2` だけです。ソースから作り直すには CMOC と LWTOOLS が要ります
(`tools/install_cmoc.sh`、ネットワークが必要)。辞書の作成には Python 3 と SKK の辞書 (`SKK-JISYO.L`) が要ります。
ビルド済みモジュールには CMOC の実行時ライブラリが含まれるため、**モジュールとしては GPL v3** です (ソースは MIT。[LICENSES.md](../LICENSES.md)、[CREDITS.md](../CREDITS.md))。

## 9. 別の環境への移植の手順 (案)

1. **ANSI 端末のある OS-9 (6809)** で使うなら、`jwp` と `skk.dic` をコピーし、文字コードの伝え方 (3 章) だけ合わせます。
   当面は `enc = opts[20]` を、コマンドラインの `-k utf8|euc|sjis` に変える修正が最小です。
2. **ANSI でない端末** (FM-11 の本来の画面など) では、4 章の出力 (`oc()` で組み立てて `sc_write(1, …)` に渡す部分: `rowbegin` `rowend`
   `scrollrows` `statusline` `redraw` の中のカーソル移動) を、機種の画面関数に置き換えます。行を描く先を 1 か所
   (`rowend`) にまとめてあるので、描画だけを差し替える構成にできます。入力 (4.3) も、機種のキーコードに合わせて `getkey()` を直します。
3. **メモリの少ない機械**では、6 章のバッファを小さくします。SKK が不要なら、`skk.c` を外すと約 9KB 小さくなります
   (`#include "skk.c"` と `skk_key` / `skk_init` の呼び出しを外す。今は条件コンパイルの切り替えは用意していません)。
4. 変更したら `tests/jwp_test.py` (`make test-jwp`) を、端末エミュレータとシミュレータで実行して確認します。
   テストは、出力した制御列を内蔵の簡易ターミナルに通して画面を検査するので、ANSI 以外の端末に変えたときは、
   その簡易ターミナルも差し替える必要があります。
