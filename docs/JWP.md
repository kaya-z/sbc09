# jwp — OS-9 用 日本語ワードプロセッサ

`jwp` は OS-9 (NitrOS-9) の上で動く**全画面の日本語ワードプロセッサ**です。シミュレータ内の 6809 で実行される
OS-9 コマンドで、Level 1 / Level 2 のどちらでも動きます (C で書き、CMOC でコンパイルしたもの)。

* UTF-8 / EUC-JP / Shift_JIS のコンソールに対応 (`kmode` の設定を自動で使う)
* 全角文字は 2 桁で表示、カーソル移動・削除・バックスペースは**文字単位**
* 画面幅での**自動折り返し** (行頭禁則・行末禁則 / 英単語は空白で折り返し)
* 変更部分だけを描き直す (端末の行挿入・行削除を使って高速にスクロール)
* 検索、切り取り/貼り付け、**整形出力** (折り返しを実際の改行にした印刷用ファイルを作る)
* **SKK 方式の仮名漢字変換** (ローマ字入力、`▽`/`▼`、送り仮名、辞書登録と学習)。辞書はメモリに置かず、**ディスク (フロッピー) 上のファイルを二分探索**する
* ファイルの改行形式 (OS-9 の CR / LF / CRLF) を自動判定して、同じ形式で書き戻す
* メッセージは端末の文字コードで日本語表示 (文字コードが `off` のときは英語)

## 使い方

```
OS9:chx /v0/cmds                 (-v os9/level1 など、jwp をインストール済みのホストのディレクトリ)
OS9:jwp memo.txt                 ファイルを開く (なければ新規)
OS9:jwp -w 60 -e 36 手紙.txt     窓幅 60 桁、整形出力の幅 36 桁
```

端末の日本語入力 (IME) で入力した文字はそのまま入ります。OS-9 側の文字コードは `kmode` で確認・変更できます
(既定 ROM は UTF-8、`os9v1_euc.rom` / `os9v1_sjis.rom` は EUC-JP / Shift_JIS。[KANJI.md](KANJI.md) 参照)。
起動時に `kmode off` (1 バイト) だと、日本語は扱えず 8 ビット文字をそのまま通します。

| オプション | 意味 |
|---|---|
| `-w 桁` | 窓の幅 (20..100、既定 80) |
| `-h 行` | 窓の高さ (6..50、既定 24。下 2 行はステータス行とメッセージ行) |
| `-e 桁` | 整形出力 (`^X`) の幅 (10..100、既定 72) |
| `-d ファイル` | SKK 辞書 (既定 `/d1/skk.dic`) |
| `-u ファイル` | SKK のユーザ辞書 (既定 `/d1/skkuser.dic`) |

画面の下から 2 行目 (反転) がステータス行です: ファイル名、`[変更]`、桁 (全角は 2)、位置/全バイト数、改行形式、文字コード。
一番下の行はキーの一覧、または直前の操作のメッセージです。

## キー

| キー | 動作 | キー | 動作 |
|---|---|---|---|
| `←` `→` / `^B` `^F` | 1 文字 左/右 | `^S` | 保存 |
| `↑` `↓` / `^P` `^N` | 1 行 上/下 (表示桁を保つ) | `^W` | 名前を付けて保存 |
| `^A` `^E` / `Home` `End` | 行頭 / 行末 (表示行) | `^O` | 別のファイルを開く |
| `PgUp` `PgDn` / `^U` `^V` | 1 画面 上/下 | `^R` | 検索 (文字列を入力して Enter) |
| `ESC <` / `ESC >` | 文書の先頭 / 末尾 | `^T` | 次を検索 (最後まで行くと先頭に戻る) |
| `BS` `^H` `DEL` | カーソルの左の 1 文字を削除 | `^K` | 行末まで切り取り (行末では改行を切る) |
| `^D` / `Delete` | カーソルの位置の 1 文字を削除 | `^Y` | 貼り付け (`^K` を続けると溜まる) |
| `Enter` | 改行 (段落を区切る) | `^X` | 整形出力 |
| `Tab` | 全角空白 (字下げ) を入れる | `^G` | 改行形式を CR → LF → CRLF と切り替え |
| `^L` | 画面を描き直す | `^Q` | 終了 (変更があれば確認) |
| `^J` | かな入力モードにする (SKK) | `l` | (かなモードで) 英数モードに戻す |

ファイル名などの入力行では `BS` が 1 文字ずつ、`Enter` で確定、`^G` で取り消しです。`^W` と `^O` では
最初に今のファイル名が入っているので、`BS` で消してから新しい名前を打ってください。

`^C` `^E` `^Q` `^S` `^W` `^X` など OS-9 が特別に扱うキーは、`jwp` が実行中だけ端末の設定 (`SS.Opt`) を
素通しにして受け取り、終了時に元に戻します。

## 折り返し (禁則処理)

行は、窓の幅 (既定 80 桁) を超える手前で次の規則に従って折り返します。

* 行頭に来てはいけない文字 (`、。，．・：；？！゛゜ゝゞ々ーぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮヵヶ）〕］｝〉》」』】` と ASCII の `,.:;?!)]}`) は、
  前の文字を巻き込んで (最大 3 文字) 次の行へ送ります (追い出し)。
* 行末に来てはいけない文字 (`（〔［｛〈《「『【` と ASCII の `([{`) は、次の行へ送ります。
* 英数字の単語は、行に入りきらないとき最後の空白で折り返します。空白は右端にぶら下がります (描きません)。
* 折り返しは画面上の表示だけで、ファイルには入りません。**段落の区切りは `Enter` の改行だけ**です。

文字の表示幅は、UTF-8 では Unicode の東アジアの幅 (全角・ひらがな・カタカナ・漢字・全角記号は 2、半角カナは 1、
`※` `○` `→` など曖昧幅は 1)、EUC-JP / Shift_JIS では 2 バイト文字を 2、半角カナを 1 とします。

## 整形出力

`^X` でファイル名を入力すると、**折り返しを実際の改行にした**ファイルを作ります (幅は `-e`、既定 72 桁、
禁則処理つき)。元の文書はそのままです。OS-9 の `list` でプリンタ (`list out.txt >/p`) や端末に出せます。

## かな漢字変換 (SKK)

端末の IME を使わなくても、OS-9 の中だけで日本語を入力できます。SKK (Simple Kana to Kanji conversion program) の作法です。
文字コードが UTF-8 / EUC-JP / Shift_JIS のとき使えます (`kmode off` では無効)。起動時は英数モードで、状態は
ステータス行の最後に `かな` / `カナ` / `英数` で出ます。

| 操作 | 動作 |
|---|---|
| `^J` | 英数モード → ひらがなモード (かなモードでの `^J` は Enter) |
| `l` | かなモード → 英数モード |
| `q` | ひらがな ⇄ カタカナ (読みの入力中なら、読みをカタカナにして確定) |
| ローマ字 | `ka`→か `kya`→きゃ `kitte`→きって `kanji`→かんじ `onna`→おんな `-`→ー `,`→、 `.`→。 `[`→「 `]`→」 |
| 大文字から始める | `Kanji` で読みの入力 `▽かんじ` (大文字は読みの始まり) |
| `Space` | 変換。`▼漢字` のように候補を見せる。もう一度 `Space` で次の候補、`x` で前の候補 |
| 5 つ目の候補から | 下の行に `a:候補 s:候補 d:… f: j: k: l:` が並び、そのキーで選べる (`Space` は次の 7 つ) |
| `Enter` / 他のキー | 候補を確定 (`Enter` では改行しない。他のキーは確定してからそのキーの動作) |
| `^G` | 変換を取り消して `▽` の読みに戻る / 読みの入力を取り消す |
| `BS` | 読みの 1 文字を消す |
| 送り仮名 | 送り仮名の頭を大文字に: `KaKu`→`書く` (辞書の読みは `かk`)、`OkuRu`→`送る`、`TabeRu`→`食べる` |
| `/` | 略語モード: `/abc` + `Space` で ASCII の読みを引く |
| 候補がないとき | `辞書登録 よみ:` と聞くので、語を入力して Enter (ユーザ辞書に登録され、そのまま入る)。空なら取り消し |

* `▽` `▼` は文書の中に実際に入る文字で、確定するか取り消すと消えます (入力の途中で保存すると残ります)。
* 先頭以外の候補を選ぶと、ユーザ辞書に `よみ /候補/` が追加され、**次からはその候補が先頭**に出ます (学習)。
* 未対応: 連文節変換、全角英数モード (`L`)、数値変換、接頭辞/接尾辞 (`>`)、`(concat ...)` などの Lisp の候補 (読み飛ばし)、
  注釈 (`;` 以降は捨てる)。

### 辞書とディスク

辞書は SKK の辞書と同じ 1 行 1 語のテキスト (`よみ /候補/候補/`) で、**読みの順に整列**してあり、行末は OS-9 の CR、
文字コードは OS-9 のコンソールと同じです。`jwp` は辞書をメモリに読み込まず、256 バイトのブロック単位で二分探索します
(SKK が整列した辞書ファイルを引くのと同じ方法)。4.5MB の辞書でも変換 1 回に十数ブロックを読むだけで、実時間でも 0.3〜0.4 秒です。
フロッピーに辞書を置いて読む、という使い方がそのまま成り立ちます。

```sh
sudo apt install skkdic                    # SKK-JISYO.L (GPL v2 以降) が /usr/share/skk に入る
make -C os9/skk                            # SKK_utf8.dsk SKK_euc.dsk SKK_sjis.dsk (各約 4〜5MB の RBF ディスク)
make -C os9/skk floppy                     # SKK_fd_*.dsk: 720K の「フロッピー」(短い読みの語を優先して 600K に絞ったもの)
./sim09 -rom os9/os9v1.rom -0 os9/OS9.dsk -1 os9/skk/SKK_utf8.dsk -v os9/level1
```

```
OS9:chx /v0/cmds
OS9:dir /d1                     skk.dic  (辞書)   skkuser.dic (使い始めると作られるユーザ辞書)
OS9:jwp memo.txt                ^J でかなモード。Kanji<Space>
```

ROM の文字コードに合う辞書ディスクを使ってください (`os9v1.rom` = utf8、`os9v1_euc.rom` = euc、`os9v1_sjis.rom` = sjis)。
ユーザ辞書も `/d1` (辞書ディスク) に作られるので、学習した内容はディスクイメージに残ります。ほかの場所の辞書は
`-d` / `-u` で指定します (`jwp -d /v0/skk.dic -u /v0/skkuser.dic memo.txt`)。

* `tools/mkskkdic.py` が辞書を作ります: 2 つの節 (送り仮名あり/なし) を 1 つに併せて整列し、注釈と Lisp の候補を除き、
  文字コードに変換 (Shift_JIS に無い字の候補は落とす)、1 行は 600 バイトまで。`-b KB` で大きさを制限できます
  (SKK の辞書には頻度がないので、短い読みを優先する単純な方法です。一般の語が欠けます)。
* `tools/mkrbf.py` が RBF ディスクイメージを作ります (ファイルは連続した 1 つのセグメントなのでシークが安い)。
* ユーザ辞書は追記だけのテキストで、変換のたびに全部読みます。1 万行 (数百 KB) を超えるほど育てると遅くなるので、
  ホスト側で整理してください (普通のテキストファイルです)。

## ファイルと改行

* OS-9 のテキストファイルの行末は CR (`$0D`) です。`jwp` は最初の行末を見て、CR のみ (OS-9)、LF (ホストで作ったファイル)、
  CRLF のどれかを判定し、内部では LF にして編集し、**判定した形式で書き戻します**。改行のないファイルと新しいファイルは CR です。
* 保存は同名のファイルを一度消してから作り直します (OS-9 にはファイルの切り詰めがないため)。
* 文書の大きさの上限は **Level 1: 9000 バイト、Level 2: 26000 バイト**です (Level 1 は空き RAM が約 44KB で、モジュールが 29KB を使います)。
  UTF-8 で全角約 3000 / 8700 文字、EUC-JP / Shift_JIS で約 4500 / 13000 文字です。それを超えるファイルは先頭だけを読み込み、
  `大きすぎます` と表示して、**同じ名前での保存を拒否**します (`^W` で別名保存は可)。
* 文字コードの変換はしません。ファイルは端末と同じ文字コードのバイト列のまま読み書きします。
  ホスト側の UTF-8 のファイルを EUC-JP の OS-9 で開くと `?` が並びます (逆も同様)。`iconv` で変換してください。
* 不正なバイト列は `?` で表示します (ファイルは壊しません)。

## ビルド

配布物にはビルド済みの `os9/jwp/jwp` (Level 1 用、29KB) と `os9/jwp/jwp-l2` (Level 2 用、バッファが大きい) が入っていて、
`make` で `os9/level1/cmds/jwp` と `os9/level2/cmds/jwp` にコピーされます。ソースから作り直すには CMOC が必要です:

```sh
tools/install_cmoc.sh $HOME/cmoc          # lwtools と CMOC をビルド (ネットワークが要ります)
make -C os9/jwp PATH=$HOME/cmoc/bin:$PATH # jwp と jwp-l2 を作る (msgs.h は genmsgs.py が生成)
make -C os9 cmds                          # level1/cmds, level2/cmds にコピー
```

* `genmsgs.py` は画面のメッセージ、禁則文字の表、全角空白を UTF-8 / EUC-JP / Shift_JIS のバイト列で `msgs.h` に出力します。
  メッセージを変えるときはここを編集します。
* `-DBUFSZ=n` でバッファの大きさを変えられます (`int` で位置を持つので 32000 以下)。Level 1 は空き RAM (約 44KB) にモジュール (29KB) と
  データを収める必要があり、約 9500 バイトが限度です。Level 2 の 1 プロセスは 64KB で、プログラムとデータを 8KB 単位に切り上げて収めます。
* **モジュール名は出力ファイル名です**: `cmoc -o /tmp/x/jwp` のようにパスを付けると、モジュール名が長すぎてモジュールディレクトリに入れず
  (`ERROR #206`)、実行できません。`-o jwp` で作ってください。

## しくみ

* **バッファ**: カーソル位置に隙間を持つギャップバッファ (カーソル移動で隙間を動かす)。
* **表示行の配置 (layout)**: 窓の各行の開始位置・終了位置・先読みした範囲を覚えておき、1 回の編集のあとは
  影響を受ける行からだけ配置し直します。新しい行の終わりが、編集量だけずらした古い行の開始位置と一致したら、
  それ以降の行は同じなので配置をやめます (`layout()`)。
* **描き直し (plan)**: 描いた行の位置を覚えておき、新しい行が古い行と同じ内容なら描きません。行が上下に動いただけなら、
  端末の行挿入 (`ESC [ n L`) / 行削除 (`ESC [ n M`) (スクロール領域は窓の行) を使います。描いた行は 2 つの 16 ビットの
  ハッシュで以前の内容と比べ、変わっていなければ送りません。
* **端末**: ANSI のカーソル移動・行消去・反転・スクロール領域・行挿入削除だけを使います。
* **入力**: OS-9 の `I$Read` を 1 バイトずつ使い、`ESC [ A` などのカーソルキーと多バイト文字は続きのバイトを読んでから処理します。
* **SKK** (`skk.c`): ローマ字の表は `genmsgs.py` が (かなの番号と 255 の組として) 生成し、かなのバイト列は文字コードごとに `kanabytes()` が作ります。
  読み (`▽`) と候補 (`▼`) は文書のバッファの中に置き、確定や取り消しでその範囲を置き換えます。辞書は 256 バイトのブロックのキャッシュを持つ
  読み出し部 (`rd_open` `rd_start` `rd_line`) と、整列した行への二分探索 (`dict_lookup`) からできています。

## テスト

`tests/jwp_test.py` (`make test-jwp`)。シミュレータの `-script` で jwp にキーを送り、出力した端末制御列を簡易ターミナル
(80x24、全角は 2 桁、スクロール領域・行挿入削除対応) に通して、**画面に見えるもの**と保存したファイルを検査します。

* 読み込み・編集・保存、日本語の BS / カーソル / 削除、ステータス行、LF / CRLF の保持、検索・切り取り・貼り付け、整形出力
* 折り返し (全角 100 桁の行は 40 文字で折れる)、禁則 (UTF-8 / EUC-JP / Shift_JIS)、英単語の折り返し
* スクロール、`^V` / `ESC >`、上下移動の表示桁、終了確認、別名保存、Level 1 / 2 のバッファの大きさ
* **SKK**: ローマ字 (ひらがな・カタカナ・っ・ん・ー・句読点)、変換・次候補・前候補・取り消し、送り仮名、候補一覧 (a s d f j k l)、`▽` `▼`、`q`、略語、
  辞書にない語の登録、ユーザ辞書の優先と学習、辞書がないとき、UTF-8 / EUC-JP / Shift_JIS、乱数のキー列での差分描画の一致、
  **`SKK-JISYO.L` 全体 (4.5MB) に対する二分探索** (乱数で選んだ 24 語の第一候補が一致すること、Level 1/2。`skkdic` があるときだけ実行)
* **乱数による編集テスト**: 乱数で作った文章に乱数のキー列 (入力・BS・Delete・Enter・カーソル・改ページ・切り取り) を送り、
  最後の画面とカーソル位置が、`^L` (全部描き直し) したものと一致することを確認します。
  `make -C os9/jwp jwp_chk` で作る検査用ビルド (`-DSELFCHECK`) では、キーごとに「配置のキャッシュが一から配置し直した結果と
  同じ」ことをプログラム自身が検査し、食い違うと `LAYOUT-BUG` を出力します (CMOC があるときだけ実行されます)。

## 制限

* ファイル全体がメモリに載る大きさまでです (上記)。複数のウィンドウ、取り消し (undo)、ルビ・縦書き・連文節変換はありません。
  SKK 方式ではなく通常の IME で入力したいときは、端末側の IME をそのまま使えます。
* 端末の大きさは取得せず、`-w` / `-h` で指定します (既定 80x24)。
* 1 つの表示行は最大 100 桁です。
* タブ文字 (`$09`) を含むファイルは、タブを空白 1 つの幅で表示します (編集で `Tab` を押すと全角空白が入ります)。
* 実時間 (1.8432MHz 相当) で、キー入力から表示まで通常 0.1〜0.3 秒です (全画面を描き直す改ページは 1〜2 秒)。`-max` を付けると
  ホストの速さで動きます。
